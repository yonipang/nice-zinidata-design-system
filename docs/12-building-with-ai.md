# 12. Claude로 만들 때

## 판단 순서

1. **README → 이 Handbook → 컴포넌트 카드** 순서로 읽는다. 더 자세한 근거가 필요하면 `reference/`의 원문(작업요약이 최우선).
2. 화면에 필요한 UI를 **컴포넌트로** 고른다([컴포넌트 고르기](08-components.md)). 없으면 가장 가까운 컴포넌트 + 토큰으로 만들고 알린다.
3. 색 · 간격 · 모서리 · 그림자 · 글자는 **토큰 이름 그대로**. 값을 그림에서 추측하지 않는다.
4. 문서에 없는 판단(새 패턴, 애매한 선택)은 **임의로 정하지 말고 묻는다.**
5. 다 만든 뒤, 토큰과 다른 값을 쓴 곳이 있으면 목록으로 알린다.

## 동작 · 기능이 정의되지 않았을 때

- 컴포넌트는 **전체 검토 전**이다. 모양 · 구조 · 속성은 쓸 수 있지만, 세부와 **동작 · 기능**(검색어 강조, 자동완성, 정렬 · 필터 동작 등)은 검토하면서 정해진다.
- 필요한 동작이 [13. 동작 · 인터랙션](13-interactions.md)에 있으면 그대로 따른다.
- 문서에 아예 없는 동작은 **임의로 만들지 말고 묻는다.** 묻기 어려운 상황이면 가장 단순한 동작(상태 변화 없음)으로 두고 알린다.
- 동작을 표현할 때도 색 · 굵기 · 그림자는 토큰과 규칙 안에서만(새 색 · 새 효과 금지).

## 금지 사항 체크리스트

- [ ] hex · Primitive 색 직접 사용(예외: 차트 · 분류 배지 · 브랜드 색)
- [ ] zinc 외의 회색(gray · slate · neutral · stone)
- [ ] 컴포넌트와 비슷한 모양을 새로 그리기
- [ ] 아이콘에 `fill-*`
- [ ] 상태(hover 등)를 화면에서 직접 색으로 칠하기, hover와 selected를 같은 모양으로
- [ ] 임의 간격 · 모서리 · 글자 크기, 대괄호 임의 값
- [ ] `shadow-*`나 직접 값으로 그림자, 버튼 · 입력창에 그림자, solid 버튼에 테두리
- [ ] 한 프로젝트에서 rounded · pill 섞기
- [ ] 한 영역에 solid 버튼 2개 이상, 표 안 줄마다 solid
- [ ] 표: 헤더 셀을 본문에, 본문 값 칸에 색 네모, 표 배경에 surface 직접, 행 36px 초과, 숫자 왼쪽 정렬
- [ ] 작은 레이블이 넘치는데 그 컴포넌트를 그대로 쓰기
- [ ] 새 이름에 bold · default(단계) · base(단계) · white · hint
